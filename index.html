What you get per instruction

LayerWhat it shows
Glyph + emojian SVG picture and an emoji of what the instruction does — 🧱 stack, ⚖️ compare, 🔀 branch, 🛡️ interrupts off
Hardware tableone row per piece of hardware with a direction: R read, W write, – explicitly preserved. Flags are per-bit: CMP writes six, MOV writes none, INC leaves CF alone
3D diethe CPU blocks the ISA requires, lit green and raised
Memory cellsthe real kernel bytes at that PC, read from the vmlinux image. The instruction's own bytes are lit; the rest are context
Register bank16 registers with live values. Registers the instruction actually touches are prominent; a register that just changed lights amber
Truth checkISA claims are cross-checked against the real trace. A conflict badge fires when the ISA said "preserved" but the hardware changed it anyway

Build it yourself

Any kernel symbol with DWARF traces the same way — the tool is not syscall-specific:

python3 trace-kernel.py --symbol __schedule --steps 90 -o t.json
python3 build-viewer.py t.json -o sched.html
Trace: real Linux v6.8.0 booted in QEMU, stepped instruction by instruction over the GDB stub, state sampled before every instruction. Floorplan and highlighting all derive from one BLOCKS table, so the 2D map, the 3D die and the hardware table cannot disagree.
